# אתרים של לקוחות: בנייה, אחסון ועלייה לאוויר

הדמואים ב-`demos/` הם חלון הראווה. לקוח שמשלם מקבל אתר משלו בתיקייה `clients/<slug>/`: התוכן, התמונות והמספר שלו, בלי שום סימן של דמו, בכתובת ובדומיין שלו.

אתר לדוגמה, מוכן מקצה לקצה: `clients/sample-plumber/` (עסק בדוי, נבנה מדמו האינסטלטור).

## ממה בנוי אתר של לקוח

| קובץ | מה הוא |
| --- | --- |
| `index.html` | הדף. מתחיל מהעתקה של דמו התחום, ומנקים ממנו את סימני הדמו |
| `assets/leadbot.js`, `assets/leadform.js` | הצ׳אט והשליחה למערכת הלידים. עותק קבוע, כך ששינוי בדמואים לא משנה אתר שכבר באוויר |
| `assets/photos/` | התמונות של הלקוח (WebP, עד ~300KB כל אחת) |
| `assets/favicon.svg` | אייקון לטאב |
| `privacy.html` | הודעת פרטיות: מה נאסף, למה, כמה זמן נשמר, איך מבקשים מחיקה. חובה כשאוספים שם וטלפון |
| `accessibility.html` | הצהרת נגישות עם איש קשר. חובה לפי תקנות הנגישות |
| `_headers` | כותרות אבטחה. `noindex` רק לאתר לדוגמה, לא ללקוח |
| `CLIENT.md` | כרטיס הלקוח: חבילה, כתובת במערכת, תאריך עלייה. לא עולה לאתר. **הריפו ציבורי: בלי טלפון אישי, בלי סכומים ובלי פרטים פרטיים.** אלה נשמרים מחוץ לריפו |
| `netlify.json` | לאן מעלים: `{ "siteId": "...", "tokenSecret": "NETLIFY_TOKEN_<SLUG>" }`. לא עולה לאתר |

האתר עומד בפני עצמו: אין בו קישורים ל-`demos/`, ואפשר להעלות אותו לכל חשבון Netlify.

## איך מעתיקים דמו לאתר אמיתי

ה-skill `new-client-site` עושה את זה. בקצרה, מה שהשתנה בין `demos/plumber/` ל-`clients/sample-plumber/`:

1. נמחקו: פס הדמו, "מחירים להמחשה", "הדף לדוגמה", "כל תמונה כאן מתחלפת", הקישור לדמואים בפוטר, מצב העריכה (`photoslots.js`, `data-edit`).
2. התמונות הפכו ל-`<img>` רגילות מתוך `assets/photos/`.
3. נוספו: `og:` לשיתוף בוואטסאפ, אייקון, `<main>`, ודפי פרטיות ונגישות עם קישור בפוטר. האדום של הכפתורים הוכהה מעט כדי לעמוד ביחס ניגודיות 4.5.
4. שאלת הטלפון בצ׳אט אומרת שיישלח אישור בוואטסאפ. Meta דורשת שהגולש יידע על ההודעה לפני שהיא נשלחת, ובלי זה המספר של העסק בסיכון.
5. הצ׳אט מקבל `capture`: הפנייה נשמרת במערכת, הלקוח מקבל אישור בוואטסאפ מהעסק, ובעל העסק מקבל התראה. אם המערכת לא עונה, הצ׳אט נותן כפתור וואטסאפ כמו בדמו. אף פנייה לא הולכת לאיבוד.
6. כל הכתובות והמספר נמצאים במקום אחד בראש הסקריפט: `const SITE = { whatsapp, leads }`.

לקוח בחבילת נוכחות: בלי `capture` ובלי שורה במערכת. הצ׳אט פותח וואטסאפ ישירות.

## אחסון: איפה האתרים יושבים

**ההמלצה: כל לקוח בחשבון Netlify חינמי משלו.**

- זה הכלל שלנו ממילא: האחסון רשום על שם הלקוח.
- לכל חשבון מכסה חודשית משלו. אם לקוח אחד חורג, רק האתר שלו נעצר, לא כל האתרים ולא מערכת הלידים.
- זה לא עולה לך כלום, ומספר הלקוחות לא מוגבל.

האפשרות השנייה: כל האתרים בחשבון שלך, במסלול בתשלום, ומעבירים אתר ללקוח אם הוא עוזב. פשוט יותר לניהול, אבל כל האתרים חולקים מכסה אחת.

### כמה Netlify סוחב

Netlify עובד היום בקרדיטים חודשיים לכל חשבון (Free: 300, Personal: 1,000, Pro: 3,000). כשהקרדיטים של חשבון חינמי נגמרים, האתרים שבו נעצרים עד החודש הבא. המספרים מ-Netlify משתנים, אז בודקים ב-netlify.com/pricing לפני שמחליטים.

| מה צורך קרדיטים | בערך |
| --- | --- |
| העלאה לאוויר (deploy) | 15 קרדיטים כל אחת |
| תעבורה | 20 קרדיטים ל-GB |
| אתר כמו `sample-plumber` | ~160KB לכניסה. 1,000 כניסות בחודש ≈ 0.16GB ≈ 3–4 קרדיטים |

כלומר אתר של עסק קטן בחשבון חינמי משלו צורך בערך 20–50 קרדיטים בחודש (תנועה ועוד שתיים-שלוש עריכות), מתוך 300. יש הרבה מרווח.

מה שכן צריך לשמור עליו:

- **לא להעלות שוב ושוב.** כל העלאה היא 15 קרדיטים. מרכזים שינויים ומעלים פעם אחת.
- **מערכת הלידים יושבת באתר שלך (service-pro-web).** כל הפניות, הצ׳אטים והתזכורות של כל הלקוחות עוברים דרכו. אם החשבון שלך נעצר, הטפסים אצל כולם נופלים לוואטסאפ (לא הולך לאיבוד, אבל בלי המערכת). **כשנכנס הלקוח המשלם הראשון, להעביר את החשבון שלך למסלול Personal**, כדי שלא ייעצר.

## עלייה לאוויר (פעם אחת לכל לקוח)

1. **חשבון Netlify על שם הלקוח**, עם המייל שלו (אפשר לפתוח אותו יחד איתו בשיחה).
2. בחשבון: Add new project → Deploy manually → גוררים את התיקייה `clients/<slug>/` (בלי `CLIENT.md`). נוצר אתר.
3. Project configuration → General: מעתיקים את ה-**Project ID**.
4. User settings → Applications → Personal access tokens: יוצרים טוקן. הטוקן נכנס **רק** ל-GitHub: Settings → Secrets and variables → Actions → `NETLIFY_TOKEN_<SLUG>` (אותיות גדולות, `_` במקום `-`).
5. בריפו: `clients/<slug>/netlify.json`:
   ```json
   { "siteId": "<Project ID>", "tokenSecret": "NETLIFY_TOKEN_OREN_MAYIM" }
   ```
6. מעכשיו כל שינוי ב-`clients/<slug>/` שממוזג עולה לבד, דרך `.github/workflows/deploy-clients.yml`. אפשר גם להריץ ידנית: Actions → Deploy client sites → Run workflow → שם התיקייה.
7. **דומיין:** Domain management → Add a domain. הדומיין נקנה על שם הלקוח. אצל רשם הדומיין מכוונים את ה-DNS לפי מה ש-Netlify מציג, ו-HTTPS נוצר לבד.
8. **מערכת הלידים:** הכתובת של האתר נכנסת ל-`allowed_origins` של הלקוח (עם www ובלי www, ואת כתובת ה-netlify.app). ראו `LEAD_SYSTEM.md`.

אם כל האתרים בחשבון שלך: אותו דבר, עם טוקן אחד בשם `NETLIFY_TOKEN`, ובלי `tokenSecret` ב-`netlify.json`.
