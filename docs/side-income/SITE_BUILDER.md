# בונה האתרים: הלקוח מספר, האתר נבנה

מטרה: בעל עסק ממלא את הפרטים בשיחה עם צ׳אט, מקבל דמו של **האתר שלו**, מבקש תיקונים באותה שיחה, מאשר ומשלם, והאתר נבנה. כפיר מאשר לפני שהאתר עולה לאוויר.

## ההחלטות

| נושא | ההחלטה |
| --- | --- |
| מי מאשר | הלקוח מאשר את הדמו, ואז כפיר מאשר לפני פרסום |
| מתי משלמים | אחרי שהלקוח אישר את הדמו, לפני הבנייה |
| תבנית ראשונה | אינסטלטור (מהדמו `demos/plumber/` ומהאתר `clients/sample-plumber/`) |

## המסלול

```
שיחה בצ׳אט ──► קובץ תוכן ──► דמו בקישור פרטי ──► תיקונים בצ׳אט ──► "מאשר"
                                                                     │
         אתר באוויר ◄── פרסום ◄── כפיר מאשר ◄── תשלום הקמה ◄─────────┘
```

1. **שיחה.** הצ׳אט שואל כמו בשיחת היכרות, שאלה אחת בכל פעם: שם העסק, אזור, שירותים, טווחי מחיר שמוכנים לפרסם, זמן חזרה שהעסק עומד בו, וואטסאפ, טלפון לשיחות. ואז: "תעלו 3–5 תמונות שלכם ושל העבודה".
2. **דמו.** תוך דקה: קישור לדמו בטלפון, עם התוכן והתמונות של העסק, מסומן "טיוטה".
3. **תיקונים.** "תוריד את הדוד", "תחליף את התמונה הראשונה", "הצבע כהה מדי". הצ׳אט מתקן, והדמו מתעדכן באותו קישור.
4. **אישור הלקוח.** כפתור "מאשר את האתר" בתוך הדמו. אחריו קישור לתשלום ההקמה (מלא או 3 תשלומים, לפי המחירון).
5. **אישור כפיר.** כפיר מקבל וואטסאפ: "אתר חדש מחכה לאישור", עם קישור לדמו. בלוח הניהול: "לפרסם" או "להחזיר ללקוח" עם הערה.
6. **פרסום.** התיקייה `clients/<slug>/` נכתבת לריפו, נוצרת שורה במערכת הלידים, וההעלאה האוטומטית מעלה את האתר.

מה נשאר ידני, כי אי אפשר אחרת:
- **וואטסאפ:** אימות המספר ב-Meta ואישור התבניות. בינתיים האתר עובד, והטופס פותח וואטסאפ.
- **דומיין:** קנייה על שם הלקוח.
- **Netlify:** פתיחת האתר בחשבון של הלקוח (חמש דקות). לחלופין מפרסמים בחשבון של כפיר ומעבירים אחר כך.

## איך זה בנוי

### תבנית = דמו + קובץ תוכן

היום הטקסט כתוב בתוך ה-HTML של כל דמו. כל תבנית תקבל:
- `template.html`: הדמו, עם מקומות שמורים במקום הטקסט (`{{business.name}}`, רשימת שירותים, מחירים, אזורים, שאלות).
- `schema.json`: אילו שדות יש, מה חובה, אורך מקסימלי, ואילו שדות הם עובדות שהלקוח חייב לאשר (שנים בתחום, תעודות, מחירים).

הצ׳אט ממלא שדות ולא כותב HTML, ולכן העיצוב לא נשבר. בונים את התבנית מ-`clients/sample-plumber/`, כי הוא כבר נקי מכל סימני דמו, עם דפי פרטיות ונגישות, וכבר מחובר למערכת הלידים.

### הצ׳אט

פונקציה ב-Netlify (`/api/builder`), Claude דרך ה-SDK הרשמי. בכל תור Claude מחזיר שני דברים: הודעה ללקוח, ועדכון לקובץ התוכן. העדכון נבדק מול `schema.json` לפני שנשמר.

כללים בהנחיות של הצ׳אט:
- רק עובדות שהלקוח אמר. שדה שאין עליו תשובה נשאר ריק, ולא ממציאים.
- העברית לפי כללי הבית: קצרה, ברבים, בלי הבטחות מוגזמות.
- הצ׳אט לא מבטיח לקוחות, לא מבטיח מקום בגוגל ולא קובע מחירים במקום הלקוח.

### הדמו

פונקציה מרכיבה את התבנית עם קובץ התוכן ומגישה אותה בכתובת `/draft/<id>?k=<key>`, עם `noindex`. אחרי כל שינוי רצות אוטומטית בדיקת האיכות (`qa-page`) ובדיקת העברית. אם משהו נכשל, הלקוח לא רואה גרסה שבורה: הצ׳אט מתקן קודם.

### תמונות

הלקוח מעלה מהטלפון ישר ל-Supabase Storage. פונקציה מקטינה וחותכת לגדלים של המסגרות (WebP, עד ~60KB), ומסירה נתוני מיקום (EXIF). לפני ההעלאה הלקוח מאשר שהתמונות שלו ושמותר לפרסם אותן.

### טבלה חדשה: `ls_drafts`

| עמודה | מה |
| --- | --- |
| `id`, `edit_key` | הקישור הפרטי (רק hash של המפתח נשמר) |
| `template` | `plumber` |
| `content` | קובץ התוכן (jsonb) |
| `photos` | רשימת התמונות והחיתוכים |
| `status` | `draft` → `client_approved` → `paid` → `published`, או `returned` עם הערה |
| `messages` | השיחה, לצורך המשך |
| `phone` | של בעל העסק, לחזרה אליו |

### תשלום

קישור תשלום של ספק סליקה ישראלי שתומך בתשלומים ובחשבונית. ההחלטה איזה ספק עוד פתוחה. עד אז: קישור Bit או העברה, וכפיר מסמן "שולם" בלוח.

### פרסום

כפיר לוחץ "לפרסם", והפונקציה כותבת לריפו דרך ה-GitHub API את `clients/<slug>/`: הדף, הנכסים, `CLIENT.md` בלי פרטים פרטיים, ו-`netlify.json` אחרי שהאתר ב-Netlify קיים. המשך התהליך כמו היום (`CLIENT_SITES.md`).
