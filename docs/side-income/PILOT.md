# פיילוט: שלושה בעלי עסקים ראשונים, בלי תשלום

המטרה: שלושה בעלי עסקים בונים לעצמם אתר אמיתי בבונה, האתר עולה לאוויר, והם משתמשים בו שבועיים. אנחנו לומדים איפה הם נתקעים ומה הם אוהבים. בלי תשלום ובלי התחייבות.

## איך זה עובד

1. כל בעל עסק מקבל קישור אישי: `https://service-pro-web.netlify.app/build/?p=<קוד>` (אפשר להוסיף גם `&t=<תחום>`, למשל `&t=barber`).
2. הוא ממלא שם ונייד, בונה את האתר בצ׳אט ובשאלון, מעלה תמונות ומאשר. מעל הטופס כתוב לו שזה פיילוט בלי תשלום.
3. אחרי האישור אין שלב תשלום. כתוב לו: "זה פיילוט, אז אין תשלום. אנחנו עוברים על האתר ומעלים אותו לאוויר, ונעדכן אתכם בוואטסאפ."
4. ב-`/build/admin/` האתר מסומן "פיילוט · <קוד>", ויש כפתור "לפרסם" (אין "התשלום התקבל"). בוחרים כתובת (למשל `dana-nails`) ומפרסמים.
5. האתר עולה לאוויר לבד: נשמר ב-`clients/<slug>/`, נפרס ב-Netlify, ומקבל כתובת (ראו "הכתובת של האתר" למטה).
6. שולחים לבעל העסק את הכתובת. בחבילת נציג AI גם את הקישור ללוח הפניות, שמופיע אחרי הפרסום.

קוד לא מוכר בקישור = בונה רגיל עם תשלום. הקודים נבדקים בשרת.

## לפני ששולחים את הקישור הראשון

### 1. משתנים ב-Netlify (רק שם, לא בצ׳אט ולא בקוד)
באתר service-pro-web, ב-Site configuration ← Environment variables:

| משתנה | למה | חובה בפיילוט |
| --- | --- | --- |
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | שמירת הטיוטות, התמונות והפניות | כן |
| `ANTHROPIC_API_KEY` | הצ׳אט בבונה, "למדו את העסק שלי" והצ׳אט החכם באתרים | כן |
| `GITHUB_TOKEN` | שמירת האתר ב-`clients/<slug>/` בפרסום | כן |
| `GITHUB_BRANCH` | הענף שהאתר הראשי עולה ממנו: `claude/multitenant-business-os-9y3vc1` | כן (זו גם ברירת המחדל) |
| `NETLIFY_TOKEN` | פריסת כל אתר ב-Netlify וקבלת כתובת | כן |
| `LEADS_ADMIN_KEY` | הכניסה ל-`/build/admin/` | כן |
| `PILOT_CODES` | קודי ההזמנה, מופרדים בפסיק. למשל `dana,ori,shai` (אותיות באנגלית, ספרות ומקף) | כן |
| `SITES_DOMAIN` | הדומיין שלנו לכתובות (ראו למטה) | לא, אבל מומלץ |

את `GROW_*` לא צריך בפיילוט.

### 2. Supabase
מריצים את כל 19 ההגירות מ-`supabase/lead-system/` לפי הסדר, ב-SQL Editor. כל קובץ אפשר להריץ שוב בלי נזק.

### 3. ריצה אחת שלכם, מקצה לקצה
1. פותחים `/build/?p=<אחד הקודים>` ובונים אתר לעסק בדוי. צריך לראות מעל הטופס "קישור אישי לפיילוט".
2. מאשרים. צריך לראות "זה פיילוט, אז אין תשלום".
3. ב-`/build/admin/` לוחצים "לפרסם", בוחרים כתובת, ופותחים את האתר בכתובת שהתקבלה.
4. שולחים לעצמכם פנייה מהצ׳אט באתר. היא אמורה לפתוח וואטסאפ עם הסיכום.
5. מוחקים את אתר הבדיקה (בלוח של Netlify, ואת התיקייה ב-`clients/`).

אם משהו נתקע בשלב 3, ב-`/build/admin/` תופיע שגיאת פרסום עם הסיבה. רוב הפעמים זה משתנה חסר.

## הכתובת של האתר

יש שלוש אפשרויות:

| | איך נראית הכתובת | מה צריך | מתי |
| --- | --- | --- | --- |
| **בלי דומיין שלנו** | `dana-nails.netlify.app` | כלום. עובד מיד עם `NETLIFY_TOKEN` | אפשר לפיילוט, אבל נראה פחות מקצועי |
| **דומיין שלנו (מומלץ)** | `dana-nails.easylanding.co.il` | לקנות דומיין אחד לעסק, להעביר את ה-DNS שלו ל-Netlify, ולהגדיר `SITES_DOMAIN` | פעם אחת, וכל אתר מקבל כתובת ותעודת אבטחה לבד |
| **הדומיין של בעל העסק** | `dana-nails.co.il` | הדומיין על שם בעל העסק. ב-`/build/admin/` לוחצים "לחבר דומיין של הלקוח", ומקבלים שתי שורות שהוא מעתיק אצל החברה שבה קנה את הדומיין | אחרי הפרסום, למי שרוצה. המערכת בודקת כל שעה ומעבירה לבד כשה-DNS מוכן (כמה שעות, עד 48) |

**ההמלצה לפיילוט:** לקנות דומיין אחד קצר (למשל easylanding.co.il, אם פנוי) אצל רשם ישראלי, בערך 70–100 ₪ לשנה. ב-Netlify: Domains ← Add domain ← מקבלים 4 שרתי DNS. אצל הרשם מחליפים את שרתי ה-DNS לאלה של Netlify. אחרי שזה מתעדכן (עד יום) מגדירים `SITES_DOMAIN=easylanding.co.il`. מאותו רגע כל פרסום מקבל `<כתובת>.easylanding.co.il` לבד. אפשר להעביר לשם גם את האתר הראשי במקום service-pro-web.netlify.app, ואז לעדכן את `BUILDER_SITE_URL`.

**אפשר להתחיל בלי דומיין.** אתר שפורסם על `netlify.app` עובר לבד ל-`<כתובת>.easylanding.co.il` בפרסום הבא אחרי שמגדירים `SITES_DOMAIN`: ב-`/build/admin/` לוחצים "לפרסם שוב" על כל אתר. הכתובת הישנה ממשיכה לעבוד ומפנה לחדשה, כך שקישור שבעל העסק כבר שלח או שם בביו לא נשבר. אחרי המעבר בודקים שהאתר עולה בכתובת החדשה, ושולחים לבעל העסק את הכתובת החדשה.

**בוחרים כתובת קצרה כבר בפרסום הראשון** (למשל `dana-nails`): היא הופכת ל-`dana-nails.netlify.app` עכשיו ול-`dana-nails.easylanding.co.il` אחר כך. אם השם תפוס ב-Netlify, מתקבל `dana-nails-site.netlify.app`, וזה רק עד המעבר.

> בהמשך הוא יעבור לכתובת קבועה, <שם>.easylanding.co.il, והקישור הישן ימשיך להפנות אליה.
> אם תרצה דומיין משלך (למשל <שם>.co.il), קונים אותו על שמך אצל רשם ישראלי, בערך 70–100 ₪ לשנה, ואנחנו מחברים. זה לא חובה בפיילוט.

## מה עובד בפיילוט, ומה לא

| עובד | צריך הגדרה נוספת (לא חובה בפיילוט) |
| --- | --- |
| האתר עצמו, בנייד ובמחשב, עם התמונות, המחירון, דפי השירות והאזורים | הודעה אוטומטית ללקוח מהמספר של העסק, והתראה לבעל העסק עם "טיפלתי": דורשות WhatsApp Cloud API למספר של כל עסק (`WA_TOKEN_<SLUG>` ותבניות מאושרות ב-Meta) |
| הצ׳אט באתר אוסף את הפרטים ופותח וואטסאפ לבעל העסק עם הסיכום | תזכורות ודוח חודשי בוואטסאפ: אותו דבר |
| הצ׳אט החכם (נציג AI) עונה מהמחירון | חיבור לגוגל Search Console (`GSC_*`) |
| לוח הפניות והסטטיסטיקות (בנציג AI) | |
| עריכה עצמית: בעל העסק חוזר לקישור שלו ומשנה | |

בנציג AI בלי WhatsApp Cloud API, כל פנייה מהאתר נפתחת אצל הלקוח בוואטסאפ, והוא שולח אותה לבעל העסק. שום פנייה לא הולכת לאיבוד. ב-`/api/health` זה יופיע כהתראות שנכשלו, וזה צפוי בפיילוט.
